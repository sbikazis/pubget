# Pubget media Worker

This Worker stores media bytes in the private Cloudflare R2 bucket `pubget-media`.
The deployed Worker name is `pubget-media` and the default app endpoint is
`https://pubget-media.pubget.workers.dev`.

## Endpoints

- `GET /health`: deployment health check.
- `POST /upload`: authenticated multipart upload for small and medium files.
- `GET /presign`: creates a 15-minute signed direct-upload URL.
- `PUT /upload/{key}`: validates and accepts the signed upload.
- `GET /resolve?key=...`: returns a 10-minute signed playback URL.
- `GET|HEAD /media/{key}`: streams a signed URL, including byte-range requests
  for video playback.
- `DELETE /media/{key}`: owner-only deletion.

## Required secret

Set a cryptographically random 32-byte hexadecimal secret. Do not commit it,
add it to Flutter defines, or place it in source control:

```sh
openssl rand -hex 32 | npx wrangler secret put MEDIA_SIGNING_SECRET
```

The Worker needs the R2 bucket binding and
`FIREBASE_PROJECT_ID=pubget-aaf27`. Firebase Authentication remains the
identity provider; Firebase Storage is not the media-byte destination.

Kirari's private FFmpeg-to-R2 bridge uses Google service identity, not a
shared application secret. Firebase Functions Gen 2 requests a short-lived
Google-signed ID token from the Cloud Run metadata server with
`audience=https://pubget-media.pubget.workers.dev` and `format=full`.
The Worker validates the Google signature, issuer, exact audience, verified
service-account email, and token lifetime. The current source configuration
allows the project's default Gen 2 runtime account
`452313838148-compute@developer.gserviceaccount.com`. If a different runtime
service account is configured outside this source, update the allowlisted
email before deploying. No `KIRARI_R2_SERVICE_SECRET` is required by this
code path; `MEDIA_SIGNING_SECRET` remains required for signed media URLs.

## Deploy

```sh
npx wrangler deploy --config worker/wrangler.toml
```

## Security and rollout notes

- The bucket is private; do not enable public bucket access.
- Firebase ID tokens are verified against Google's Secure Token signing keys.
- The Worker enforces content-type, extension, size, owner, expiry, and
  leading-byte file-signature checks for multipart and streamed direct uploads.
- Signed playback URLs are bearer URLs and expire after ten minutes. Avoid
  logging their query strings.
- Generic keys (`images/{uid}/{file}`, `reels/{uid}/{file}`,
  `audio/{uid}/{file}`) are owner-scoped. Other signed-in users can resolve
  image keys only when a public profile, published group, or published event
  explicitly references the key. Event callables maintain a `mediaKeys` index
  for nested poll-option images; drafts and deleted events are not exposed.
- Conversation keys use `groups/{groupId}/{uid}/{file}` or
  `privateChats/{chatId}/{uid}/{file}`. Upload and resolve requests re-check
  the caller's Firebase ID token against Firestore Security Rules: group root
  plus membership document for groups, and participant access for private
  chats. The object metadata must also match the requested scope.
- Signed playback URLs are bearer URLs and expire after ten minutes. Avoid
  logging their query strings.
- Chat metadata is registered in Firestore only after the Worker accepts the
  R2 upload. Group/private message callables still enforce sender ownership,
  ready status, media type, and the existing messaging policy.
- Video thumbnails/transcodes are not generated by this Worker yet. The app
  currently uses the original R2 video stream and a neutral poster placeholder.
- Existing Firebase Storage objects are legacy data. Do not delete or migrate
  source objects as part of a copy operation.
- The group and private-chat byte upload paths now use Cloudflare R2. Other
  feature-specific image/video uploaders (including Reels, edits, and some
  staged group/event assets) still require migration before the app can claim
  complete Cloudflare-only media support.
