أنت تعمل الآن على إعادة بناء وتطوير نظام الملف الشخصي Profile داخل Pubget.

المطلوب ليس تعديلًا بسيطًا على الشاشة الحالية.

المطلوب هو إعادة بناء Profile System بالكامل ليصبح:

THE COMPLETE SOCIAL IDENTITY CARD OF A PUBGET USER

الملف الشخصي في Pubget يجب أن يكون المكان الذي يستطيع فيه أي شخص فهم هوية المستخدم بسرعة: من هو؟ ما رتبته؟ ما شخصيته؟ ما اهتماماته؟ ما إنجازاته؟ ما أنمياته المفضلة؟ ما أعماله؟ ما مجموعاته؟ ما أحداثه؟ وما المحتوى الإبداعي الذي يصنعه؟

لكن دون تحويل الصفحة إلى صفحة طويلة وفوضوية.

المبدأ الأساسي:

IDENTITY FIRST ↓ KEY STATS ↓ ORGANIZED DISCOVERY BUTTONS ↓ CREATIVE CONTENT

==================================================

IMPORTANT — CURRENT SCREEN IS REFERENCE ==================================================


افحص implementation الحالي في المشروع قبل التعديل.

لا تفترض أن الموجود صحيح.

قسّم الموجود إلى:

KEEP REFACTOR REPLACE REMOVE

المطلوب Rebuild وليس مجرد إضافة أزرار فوق التصميم الحالي.

احتفظ فقط بالأجزاء الجيدة والمتوافقة مع هذه المواصفة.

لا تكسر الأنظمة الأخرى.

================================================== 2. PROFILE PHILOSOPHY
Profile ليس Settings.

Profile ليس Dashboard.

Profile ليس مجرد User Card.

Profile هو:

SOCIAL IDENTITY + ACTIVITY + ACHIEVEMENTS + CREATIVE PORTFOLIO

يجب أن يشعر المستخدم عندما يدخل Profile شخص آخر أنه دخل "عالم هذا الشخص" داخل Pubget.

لكن يجب أن يستطيع فهم أهم المعلومات خلال ثوانٍ.

لذلك:

لا تعرض كل شيء مباشرة.

بدلًا من ذلك:

المعلومات الأساسية تظهر مباشرة.
الإحصائيات الأساسية تظهر مباشرة.
باقي المجالات تظهر كأزرار أنيقة ومنظمة.
Reels/Edits تظهر مباشرة لأنها المحتوى الإبداعي الرئيسي.
================================================== 3. TWO PROFILE MODES
النظام لديه وضعان:

A. MY PROFILE

B. OTHER USER PROFILE

كلاهما يستخدم نفس architecture ونفس التصميم الأساسي.

الاختلاف هو الصلاحيات والأفعال فقط.

لا تنشئ Profile UI منفصلًا بالكامل للآخرين.

================================================== 4. MY PROFILE
في ملف المستخدم نفسه:

يظهر كل المحتوى العام للمستخدم.

لكن أدوات الإدارة لا تنتشر داخل الصفحة.

كل ما يتعلق بالإدارة والتحكم يوضع داخل:

ONE MANAGEMENT BUTTON

في الـTop Bar.

هذا الزر يفتح صفحة/Bottom Sheet الإدارة التي تحتوي على:

Edit Profile
Profile settings
Privacy
Content management
Reel/content management عند الحاجة
Other profile-management actions
لا تضع Edit Profile كزر كبير مستقل داخل Body.

لا تكرر أدوات الإدارة في أكثر من مكان.

================================================== 5. OTHER USER PROFILE
عند فتح Profile لشخص آخر:

احذف بالكامل:

Edit Profile
Profile management
Owner-only controls
Friend request management الخاصة بالمالك
أي زر إداري
واستبدلها بأفعال مناسبة للمشاهد، مثل:

Respect / Fan interaction
Message عندما تسمح قواعد Pubget بذلك
Share Profile
More
لكن لا تضع عشرات الأزرار في الـTop Bar.

اجعل Top Bar نظيفًا.

================================================== 6. TOP APP BAR
أعد تصميم الـTop Bar بالكامل.

يجب أن يكون Premium ومتناسبًا مع Pubget.

في My Profile:

[Back] [Profile title/identity] [Share] [Management]

في Other Profile:

[Back] [Profile title/identity] [Share] [More]

يمكن أن تكون بعض العناصر context-aware، لكن لا تجعل الشريط مزدحمًا.

استخدم:

Material 3
RTL
Pubget iconography
subtle animations
proper safe area
لا تجعل الـAppBar يغطي الـCover.

================================================== 7. PROFILE HEADER
الجزء العلوي يجب أن يحتفظ بفكرة الشاشة الحالية:

Cover / Background + Avatar + Identity

لكن بجودة أعلى بكثير.

الترتيب:

COVER ↓ AVATAR OVERLAP ↓ DISPLAY NAME ↓ USERNAME ↓ RANK / STATUS ↓ OPTIONAL IDENTITY DETAILS ↓ BIO

================================================== 8. COVER IMAGE
Cover يجب أن يكون:

Premium
clean
responsive
correctly cropped
بدون distortion
يعمل Dark/Light mode
لا يسبب layout jump
إذا لم توجد Cover: استخدم Pubget default background أنيق.

لا تجعل default background فارغًا أو رخيصًا.

================================================== 9. AVATAR
Avatar يجب أن يكون واضحًا ومميزًا.

يظهر فوق الـCover مع:

circular/soft shape
border مناسب
rank/status indicator عند الحاجة
online status فقط إذا كان النظام الحالي يستخدمه بطريقة منطقية
لا تضف 10 badges حول الصورة.

================================================== 10. USER IDENTITY
يجب أن يظهر:

Display Name Username Rank Bio

ويمكن إظهار معلومات تعريفية إضافية إذا كانت موجودة في Profile Model.

مثل:

Roleplay name
Real/display identity according to user's privacy settings
Country
Age إذا كان المستخدم اختار إظهارها
joined date أو identity metadata إذا كانت مفيدة
IMPORTANT:

لا تعرض معلومات خاصة إذا كانت Privacy settings تمنع ذلك.

Profile privacy يجب أن تكون authoritative.

================================================== 11. BIO
في التصميم الحالي الـBio غير واضح بما يكفي.

أصلح ذلك بالكامل.

Bio يجب أن يكون:

readable
visually separated
واضح في Dark mode
واضح في Light mode
يدعم RTL
يدعم multiline
لا يسبب تمددًا غير منطقي للصفحة
إذا كان Bio طويلًا: اعرض preview + "عرض المزيد".

إذا لم يوجد Bio: لا تضع مساحة ضخمة فارغة.

يمكن عرض identity metadata بدلًا منها.

================================================== 12. RANK IDENTITY
Rank جزء أساسي من هوية Pubget.

استخدم نظام الرتب الحالي في المشروع.

لا تنشئ Rank system جديدًا.

يمكن أن يظهر Rank:

بجانب الاسم
أو تحت الاسم
أو كـbadge راقٍ
مع visual treatment مناسب
لكن لا تجعل الرتبة أكبر من اسم الشخص.

الرتبة identity، وليست الإعلان الرئيسي.

================================================== 13. PROFILE STATS
حافظ على فكرة الـStats Cards الموجودة حاليًا، لكن أعد تصميمها بجودة أعلى.

المبدأ:

KEY SOCIAL STATS ONLY

لا تعرض 15 رقمًا.

الـStats الأساسية يمكن أن تشمل حسب بيانات Pubget الحالية:

Friends / Social connections
Fans
Respect
Other meaningful profile metric
استخدم labels واضحة.

لا تستخدم أرقامًا fake.

إذا كانت metric غير موجودة فعليًا: لا تخترعها.

================================================== 14. STAT CARDS DESIGN
أعد تصميم البطاقات الحالية لتكون:

Premium
compact
elegant
readable
balanced
responsive
استخدم Pubget: Purple + Gold + Dark surfaces

لكن لا تجعل كل شيء Gold/Purple.

الأرقام يجب أن تكون العنصر الأقوى داخل البطاقة.

العنوان واضح.

الأيقونة صغيرة وليست dominant.

================================================== 15. RESPECT / FAN RELATIONSHIP
عند مشاهدة Profile لشخص آخر، يجب أن يظهر نظام Pubget الاجتماعي.

لا تستخدم Follow بشكل تقليدي.

استخدم:

RESPECT → FAN

وفق نظام Pubget الحالي.

الـinteraction الرئيسي يمكن أن يفتح Bottom Sheet لإعطاء Respect.

إذا وصل Respect إلى threshold الحالي الذي يجعل المستخدم Fan، يتم تحديث العلاقة وفق Social Graph الحالي.

لا تنشئ Followers system منفصل.

استخدم:

Respect
Fans
Social Graph
الموجودة أصلًا في Pubget.

================================================== 16. MAIN PROFILE ACTIONS
لشخص آخر، يمكن أن توجد مجموعة صغيرة من الأفعال:

Respect/Fan
Message إذا كانت شروط Private Chat متحققة
Share Profile
More
لا تجعل هذه الأفعال تأخذ نصف الشاشة.

استخدم compact action row.

================================================== 17. THE CORE STRUCTURE
بعد Header + Stats:

لا أريد Sections طويلة مثل:

Achievements Favorite Anime Fan Works Groups Events ...

كلها تفتح واحدة تحت الأخرى وتستهلك الشاشة.

بدلًا من ذلك:

أنشئ Vertical Feature Menu.

كل عنصر عبارة عن Premium Button/Card.

مثال:

[ 🏆 الإنجازات > ]

[ ◈ الأنميات المفضلة > ]

[ ✦ الأعمال > ]

[ ♟ المجموعات > ]

[ ◉ الأحداث > ]

ويمكن إضافة المجالات الأخرى ذات القيمة الحقيقية.

================================================== 18. FEATURE BUTTON DESIGN
هذه الأزرار هي جزء مهم جدًا من هوية Profile.

لا تجعلها مجرد OutlinedButton عادي.

كل زر يجب أن يحتوي على:

Icon
Title
Short contextual value
Arrow
Optional count
subtle Pubget visual treatment
مثال:

الإنجازات "12 إنجازًا مكتملًا"

الأنميات المفضلة "One Piece • Naruto • ..."

الأعمال "8 أعمال"

المجموعات "5 مجموعات"

الأحداث "3 أحداث نشطة"

لكن لا تضع نصًا إذا لم تكن البيانات متوفرة.

================================================== 19. FEATURE BUTTON ORDER
الترتيب الأساسي:

الإنجازات
الأنميات المفضلة
الأعمال / Fan Works
المجموعات
الأحداث
أي Profile domains إضافية مهمة موجودة فعليًا في Pubget
لا تضف Game Center للمستخدم إلا إذا كان هناك محتوى شخصي حقيقي يستحق عرضه.

لا تضع: Settings Store Premium Edit Profile

داخل هذه القائمة.

هذه ليست Profile identity content.

================================================== 20. ACHIEVEMENTS
الـAchievements لا تظهر كقسم طويل داخل Profile.

تظهر كزر واحد فقط:

الإنجازات

عند الضغط: → صفحة Achievements كاملة.

داخل الصفحة:

earned achievements
locked achievements
progress
categories
rarity
dates إذا كانت متاحة
لا تكرر الإنجازات في Profile.

================================================== 21. FAVORITE ANIME
يظهر كزر:

الأنميات المفضلة

يمكن أن يعرض في الزر preview صغيرًا:

One Piece • Hunter x Hunter • ...

عند الضغط:

→ Favorite Anime full page.

هذه الصفحة تعرض قائمة الأنميات المفضلة للمستخدم.

يمكن أن تتكامل مع Anime Hub.

عند الضغط على Anime: → Anime page.

================================================== 22. FAN WORKS
يظهر كزر:

الأعمال

أو اسم المجال الإبداعي الحالي في Pubget إذا كان هناك naming رسمي أفضل.

يعرض preview صغيرًا: عدد الأعمال.

عند الضغط: → صفحة أعمال المستخدم.

لا تضع كل Fan Works داخل Profile مباشرة.

================================================== 23. GROUPS
زر:

المجموعات

يظهر: عدد المجموعات أو preview مختصر.

عند الضغط: → قائمة مجموعات المستخدم.

يمكن تقسيمها منطقيًا إلى:

Created
Joined
إذا كانت البيانات الحالية تدعم ذلك.

استخدم Group entities الحالية.

لا تعيد بناء Groups.

================================================== 24. EVENTS
زر:

الأحداث

عند الضغط: → صفحة Events الخاصة بالمستخدم.

يجب أن تفرق الصفحة بين:

Live Upcoming Ended

حسب نظام Events الحالي.

لا تعرض الأحداث نفسها داخل Profile.

================================================== 25. OTHER USER ACTIVITY
Profile يجب أن يعطي صورة عن نشاط الشخص.

لكن لا نريد Activity Feed عشوائي داخل Profile.

بدلًا من ذلك يمكن أن يظهر activity summary في الأزرار/metadata:

number of creations
achievements
groups
events
favorite anime
creative content
لا تجعل Profile نسخة من Home Feed.

================================================== 26. REELS / EDITS — THE EXCEPTION
هذا أهم استثناء في Profile.

Reels/Edits لا تختصر في زر.

لأنها المحتوى الإبداعي الرئيسي للمستخدم.

بعد Feature Menu:

أو حسب التصميم الأفضل:

CREATIVE VIDEO AREA

يجب أن تبدأ منطقة Reels/Edits.

لا تجعلها Card صغيرة مثل التصميم الحالي.

لا تجعلها مجرد thumbnail واحد.

================================================== 27. CREATOR REELS LAYOUT
اعرض فيديوهات المستخدم بطريقة Short Video platform.

عند فتح Profile:

يمكن أن يظهر Preview/Grid مناسب.

لكن عند الضغط على Reel:

يفتح Full-screen Reel Viewer.

ثم:

Swipe up → next Reel

Swipe up → next Reel

Swipe up → next Reel

بنفس Reel Viewer الخاص بالنظام الرئيسي.

لا تنشئ Video Player ثانيًا للـProfile.

استخدم نفس Reels architecture.

================================================== 28. CREATOR CONTEXT
عندما يدخل المستخدم Reel من Profile:

يجب أن يعرف أنه يتصفح أعمال هذا الشخص.

يمكن للـViewer أن يستخدم creator-specific queue:

Creator Reel 1 Creator Reel 2 Creator Reel 3 ...

ولا يخلطها تلقائيًا مع Feed العام أثناء هذا السياق إلا إذا خرج المستخدم من Creator context.

================================================== 29. REELS TAB / AREA
إذا احتجت إلى Tab داخل creative section:

اجعله بسيطًا.

لا تضف: Videos Edits Reels Shorts Clips

كلها لنفس المحتوى.

استخدم الاسم الرسمي الموحد الذي سيتم اعتماده لنظام الفيديو.

================================================== 30. PROFILE CONTENT HIERARCHY
الترتيب النهائي يجب أن يكون منطقيًا بصريًا:

TOP BAR

↓

COVER + AVATAR

↓

NAME + USERNAME + RANK

↓

BIO / IDENTITY

↓

SOCIAL ACTIONS إذا كان Profile لشخص آخر

↓

STATS

↓

FEATURE MENU

Achievements Favorite Anime Works Groups Events ...

↓

CREATIVE VIDEO CONTENT

↓

END

لا تضع المعلومات المهمة في أماكن عشوائية.

================================================== 31. DO NOT CREATE EMPTY SPACE
الـProfile الحالي يحتوي على مساحات غير مستغلة ومشاكل في تحميل بعض الأقسام.

أعد بناء layout بحيث:

إذا section غير متوفر:

لا تحجز مساحة كبيرة
لا تعرض عنوانًا بلا محتوى
لا تعرض loading دائمًا
إذا data loading: → skeleton

إذا empty: → elegant empty state أو أخفِ العنصر إذا كان وجوده غير مفيد.

================================================== 32. DATA COMPLETENESS
هناك حاليًا مشكلة أن Profile قد لا يعرض جميع معلومات المستخدم بعد إدخالها.

افحص:

Profile model
Firestore mapping
serialization/deserialization
provider state
caching
update flow
وتأكد أن البيانات التي يدخلها المستخدم في Edit Profile تصل إلى Profile فعليًا.

خصوصًا:

Bio
Name
Username
Avatar
Cover
Rank
Country
Age إذا كان public
Roleplay identity
Favorite Anime
Other supported fields
لا تقم فقط بتغيير UI.

أصلح data pipeline.

================================================== 33. EDIT PROFILE
زر Edit Profile يجب أن يعمل فعليًا.

من My Profile:

Management → Edit Profile

ويجب أن يفتح شاشة التحرير الحالية أو الجديدة الصحيحة.

يجب أن يستطيع المستخدم:

تغيير avatar
تغيير cover
تغيير bio
تعديل المعلومات المسموحة
تعديل favorite anime
تعديل identity fields
privacy controls
بعد Save:

→ validation → persistence → state update → Profile refresh/update

بدون الحاجة إلى إغلاق الشاشة وإعادة فتح التطبيق.

================================================== 34. OPTIMISTIC UI
استخدم optimistic UI حيث يكون آمنًا.

مثال: تغيير Bio → local state update → save → confirm

إذا فشل: → rollback → error message → retry

لا تجعل المستخدم ينتظر spinner طويلًا.

================================================== 35. PROFILE CACHING
Profile data يتم تحميله بطريقة ذكية.

لا تعيد تحميل كل شيء عند كل navigation.

استخدم:

caching
stale-while-refresh عند الحاجة
lazy loading
selective refresh
لكن لا تعرض بيانات قديمة إلى أجل غير محدود.

================================================== 36. PROFILE PERFORMANCE
Profile يجب أن يكون سريعًا حتى على الأجهزة الضعيفة.

لا تحمل:

كل achievements
كل anime
كل groups
كل events
كل reels
مرة واحدة.

استخدم summaries + lazy navigation.

مثال:

Profile: Achievements count = 12

عند الضغط: تحميل Achievements page.

================================================== 37. REELS PERFORMANCE INSIDE PROFILE
لا تحمل كل فيديوهات creator مرة واحدة.

عند فتح Profile: يمكن تحميل أول مجموعة thumbnails فقط.

عند الدخول إلى Viewer: preload الفيديو التالي.

استخدم Reels performance architecture نفسها.

================================================== 38. PROFILE PRIVACY
احترم privacy settings.

إذا المستخدم أخفى:

Age
Country
certain identity fields
activity
other content
لا تظهر للآخرين.

Owner يمكنه رؤية بياناته وفق صلاحياته.

لا تعتمد على UI فقط.

Security rules/backend يجب أن تمنع تسريب البيانات الخاصة.

================================================== 39. PROFILE SHARE
Profile قابل للمشاركة.

أنشئ deep link مناسب مثل:

/profile/{usernameOrUserId}

عند فتح الرابط: → Profile مباشرة.

إذا التطبيق موجود: → افتح التطبيق في Profile.

إذا المستخدم غير مسجل: → يمكن مشاهدة Public Profile حسب privacy.

================================================== 40. PROFILE MORE MENU
في Other Profile:

More menu يحتوي فقط على actions المناسبة:

Report
Block
Mute
Copy username/link إذا كانت مفيدة
Other safety actions
لا تضع أدوات الإدارة.

================================================== 41. PROFILE SOCIAL RELATIONSHIP
إذا المستخدم يعطي Respect للشخص:

يجب أن يحدث ذلك عبر النظام الحالي.

لا تنشئ profile-specific relationship system.

Profile يعرض العلاقة الحالية.

مثال:

Respect 0 → يمكن إعطاء Respect

Respect 5+ → Fan

إذا كان بالفعل Fan: → أظهر Fan state بوضوح.

================================================== 42. MESSAGE BUTTON
إذا كان Private Chat متاحًا حسب شروط Pubget الحالية:

أظهر Message.

إذا لم يكن متاحًا: لا تعرض زرًا يؤدي إلى error.

إما:

لا تعرضه أو
اعرض سببًا واضحًا عند الضغط حسب UX الأفضل.
استخدم شروط Respect الحالية.

لا تغير قواعد Private Chat.

================================================== 43. PROFILE BADGES
يمكن أن تظهر badges المهمة فقط.

مثل:

Rank
Verified إذا كان النظام موجودًا
special status
achievement highlight
لكن لا تحول Profile إلى لوحة badges.

================================================== 44. VISUAL LANGUAGE
الهوية البصرية:

PUBGET ROYAL ANIME SOCIAL

Use:

Royal Purple
Gold
Deep dark surfaces
Elegant gradients
Subtle borders
Controlled glow
premium cards
لكن:

NO childish UI NO excessive neon NO random anime decorations NO visual noise

التصميم يجب أن يشعر: Luxury + Authority + Anime + Social identity.

================================================== 45. DARK MODE
Dark mode هو primary visual environment حاليًا.

لكن Light mode يجب أن يعمل.

لا تستخدم:

dark text on dark background
low contrast purple
gold text على خلفيات غير مناسبة
اختبر جميع الحالات.

Pubget عربي-first.

Profile يجب أن يكون RTL بشكل صحيح.

لكن أسماء المستخدمين والـhandles: تبقى طبيعية.

لا تقلب:

@username
URLs
hashtags
technical identifiers
إلا عند الحاجة.

================================================== 47. TYPOGRAPHY
Hierarchy:

Display Name

Username Rank Bio Stats Feature titles Secondary metadata

لا تجعل كل النصوص بنفس الحجم.

استخدم micro-interactions:

subtle button press
page transition
avatar interaction
feature card tap
stats update
Respect feedback
