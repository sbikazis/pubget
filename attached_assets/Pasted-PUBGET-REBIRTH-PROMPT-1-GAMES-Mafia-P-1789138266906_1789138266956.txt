PUBGET REBIRTH — PROMPT 1
إعادة بناء نظام GAMES بالكامل — باستثناء Mafia
أنت تعمل على إعادة بناء Pubget، وليس على ترقيع نظام الألعاب القديم.

هذه المهمة مخصصة حصريًا لـ Games Domain، مع استثناء Mafia الذي سيُعاد بناؤه في Prompt 2.

1. القاعدة الأساسية غير القابلة للتفاوض
في Pubget يوجد نظامان مستقلان تمامًا:

Games
نشاط تفاعلي قابل للعب، له:

Players
بداية
حالة لعب
نهاية
Winner / Draw / Loss
Score/Reward
Game History
Events
نظام اجتماعي مستقل، وليس لعبة.

ممنوع دمج Games و Events في Domain واحد.

لا تستخدم Event Model لتمثيل Game.

لا تجعل Game نوعًا من Event.

لا تجعل Event نوعًا من Game.

لا تنشئ abstraction مشتركة تجعل منطق النظامين متشابكًا.

الـChat يستطيع فقط استقبال رسائل نظامية ناتجة عن Game، ولكنه لا يمتلك منطق اللعبة.

البنية يجب أن تكون قابلة لإضافة ألعاب مستقبلية لاحقًا، لكن لا تضف أي لعبة مستقبلية الآن.

3. مكان إنشاء الألعاب
اللعبة لا تُنشأ من Home.

اللعبة لا تُنشأ من زر + في Home.

اللعبة لا تُنشأ من صفحة عامة.

الطريقة الوحيدة لإنشاء Game هي:

Group Chat → Game Button → Game Center/Create Game

أي أن Game مرتبط دائمًا بمجموعة ودردشة تلك المجموعة.

4. حدود إنشاء الألعاب
كل مستخدم يستطيع إنشاء:

حد أقصى لعبتين جديدتين في اليوم الواحد.

المشاركة في ألعاب الآخرين لا تُحسب ضمن هذا الحد.

الحد يخص الإنشاء فقط.

عند الوصول إلى الحد:

امنع إنشاء لعبة ثالثة.
اعرض للمستخدم سبب المنع بوضوح.
لا تنشئ Document ثم تفشل العملية لاحقًا.
التحقق من الحد يجب أن يكون Server-side وليس مجرد UI check.

يجب منع race conditions بحيث لا يستطيع المستخدم إنشاء 3 ألعاب في نفس اللحظة عبر عدة requests.

5. Mafia لها صلاحيات مستقلة
لا تطبق قاعدة إنشاء الألعاب العامة على Mafia بشكل أعمى.

Mafia لها Permission منفصلة سيتم تنفيذها في Prompt 2.

من داخل المجموعة يوجد خيار:

عند فتحه تظهر واجهة Game Center الخاصة بالمجموعة.

الواجهة يجب أن تكون Premium، واضحة، سريعة، ولا تشبه قائمة نصية بدائية.

Game Center يحتوي على أقسام منظمة:

Available Games

Recent Games

Game History
الألعاب السابقة مع نتائجها.

Rules
قواعد كل لعبة.

Game Information

عدد اللاعبين

مستوى الصعوبة
طريقة الفوز
نوع اللعبة
الألعاب الأربع متاحة دائمًا.

لا تسمح لصاحب المجموعة بإخفاء لعبة أو تعطيلها.

لا تترك Waiting Room orphaned.

12. Game Archive داخل المجموعة

14. Disconnect / App Close
إذا أغلق المستخدم التطبيق مؤقتًا أو خرج منه ثم عاد، لا تعتبره Deleted.

الـGame State محفوظ على Server.

عند العودة:

استرجع الحالة الصحيحة.
أعد المستخدم إلى المكان الصحيح إذا كانت اللعبة ما زالت تسمح بذلك.
لا تعيد تشغيل اللعبة.
لا تعيد توزيع الشخصيات.
لا تعيد خصم Reward.
أما إذا قام المستخدم بانسحاب صريح داخل اللعبة، تعامل مع ذلك حسب قواعد اللعبة.

15. Rewards
نظام المكافآت يستخدم Coins الموجود أصلًا في Pubget.

قاعدة أساسية:

Loss = 2 Coins
Draw = 5 Coins
Win = من 7 إلى 10 Coins حسب صعوبة اللعبة.
لا تجعل المكافآت ضخمة.

لا تجعل الخسارة أفضل من الفوز.

كل Reward يجب أن يُصرف مرة واحدة فقط باستخدام idempotency.

لا يمكن إعادة الحصول على Reward بإعادة إرسال request.
