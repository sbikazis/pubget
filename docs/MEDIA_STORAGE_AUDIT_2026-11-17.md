# Pubget media storage audit — 2026-11-17

## Scope and status

This audit follows the current main tree after PR #194 (Kirari R2) and the
Edits/Reels migration proposed on feat/r2-edits-mainline. A route is called
R2-backed only when the Flutter uploader, Worker endpoint, and processing/read
path are present in source. This is a code audit, not a production smoke test.
No production Worker or Firebase deployment is implied.

## Security and lifecycle observations

- The R2 bucket remains private. User uploads use Firebase ID-token authentication;
  conversation media also checks membership/participant access.
- Edits service-side object operations use the existing Google runtime identity
  validation and a strict object-key allowlist. No service-account key or
  signing secret is added to Flutter or committed source.
- Upload size, MIME type, and leading-byte signature checks remain enforced by
  the Worker. Edits upload ownership and uploading state are rechecked around
  the R2 write to avoid recreating a cancelled/deleted draft.
- Edits deletion persists the cleanup manifest and removes known R2 objects
  idempotently; pipeline failures clean partial outputs. Kirari multipart
  cancellation aborts the upload session and R2 lifecycle expiry covers
  abandoned multipart sessions.
- Firebase Storage rules are not relaxed. Existing Firebase objects are not
  copied, deleted, or bulk-migrated here. Legacy readers and object-finalize
  handling remain in place.
- No Cloud Functions deployment or Worker production deployment is performed
  by this change. The project remains on its existing Firebase plan.

## Explicit remaining work

1. Fan Works: add a dedicated R2 object namespace and Worker authorization for
   image/PDF roles, work ownership, publication visibility, signed reads,
   deletion, cancellation, and retry. Do not route PDFs through the generic
   image/video/audio endpoint.
2. Extracted audio: determine whether the legacy audioDomain callables are
   reachable from the active UI; if active, migrate source reads and audio
   writes to the appropriate R2 adapter and add tests.
3. Chat derivatives: add an R2-aware thumbnail/transcode pipeline or explicitly
   retain original-only behavior. The current GCS group-media trigger does not
   process R2 objects.
4. Group media copy/forward: groupChat.js has a GCS bucket-copy path for
   cross-group media. Verify and migrate that path before claiming R2 media
   forwarding is complete.
5. Legacy sticker/background code: establish whether any current route still
   instantiates lib_legacy services before changing storage behavior.

## Verification limits

This document describes source-level routing and tests. Authenticated live
upload → processing → playback/seek → retry → cancel → delete tests still
require a real signed-in app session and the appropriate deployed runtime.
